## The problem with ?

With five `?` in a query, the arguments must be passed in exactly the right order — and a reordered
`WHERE` clause silently binds the wrong values. Named parameters fix that.

```java
// JdbcTemplate: position matters
jdbc.query("SELECT * FROM book WHERE author_id = ? AND price < ?", BOOK, authorId, maxPrice);

// NamedParameterJdbcTemplate: names matter
named.query("SELECT * FROM book WHERE author_id = :author AND price < :max",
        Map.of("author", authorId, "max", maxPrice), BOOK);
```

## NamedParameterJdbcTemplate

Boot creates one alongside `JdbcTemplate`. It has the same methods — `query`, `queryForObject`,
`queryForList`, `update`, `batchUpdate` — but takes parameters by name.

### IN lists, for free

Bind a `Collection` and Spring expands the placeholder to the right number of `?`.

```java
List<Author> authors = named.query(
        "SELECT * FROM author WHERE id IN (:ids)",
        Map.of("ids", List.of(1L, 2L, 3L)),            // → IN (?, ?, ?)
        AUTHOR);
```

<Callout type="pitfall" title="An empty list is a syntax error">
`IN ()` is invalid SQL, so an empty collection fails at the database. Return early:
`if (ids.isEmpty()) return List.of();`. Very large lists are a problem too — thousands of
parameters make slow statements that are never cached; use a temporary table or a join instead.
</Callout>

## JdbcClient

`JdbcClient` (Spring Framework 6.1, so Boot 3.2+) is a fluent API over the same machinery. It accepts
positional **or** named parameters and maps rows to records without writing a mapper.

```java
@Repository
public class LoanRepository {
    private final JdbcClient jdbc;                     // Boot creates this bean too

    public LoanRepository(JdbcClient jdbc) { this.jdbc = jdbc; }
}
```

### The shape of every call

```text
jdbc.sql("…")                 the statement
    .param(…)                 bind values — positional or named
    .query(…) / .update()     what to do
    .list() / .single() / .optional() / .set() / .stream()   what to return
```

```java title="Reading"
// One value
int open = jdbc.sql("SELECT COUNT(*) FROM loan WHERE member_id = ? AND returned_at IS NULL")
        .param(memberId)
        .query(Integer.class)
        .single();

// Zero or one row, mapped to a record automatically
Optional<Loan> loan = jdbc.sql("SELECT * FROM loan WHERE id = :id")
        .param("id", loanId)
        .query(Loan.class)
        .optional();

// Many rows, with your own RowMapper
List<Book> books = jdbc.sql("SELECT … FROM book WHERE author_id = ?")
        .param(authorId)
        .query(BookRepository.BOOK)
        .list();

// Untyped rows
List<Map<String, Object>> rows = jdbc.sql("SELECT * FROM member").query().listOfRows();
```

```java title="Writing"
int changed = jdbc.sql("UPDATE loan SET returned_at = :at WHERE id = :id")
        .param("at", LocalDateTime.now(clock))
        .param("id", loanId)
        .update();

// All parameters from a record or a map at once
jdbc.sql("INSERT INTO member (email, full_name) VALUES (:email, :fullName)")
        .paramSource(newMember)
        .update();
```

<Callout type="pitfall" title="Do not mix positional and named parameters in one statement">
A statement uses either `?` or `:name`. Mixing them in one SQL string is not supported.
</Callout>

## Which one should you use?

<DecisionTable
  columns={['Pick it when']}
  rows={[
    { label: 'JdbcClient', verdict: 'good', cells: ['New code. One API, named or positional, records mapped for you, optional() built in'] },
    { label: 'NamedParameterJdbcTemplate', verdict: 'good', cells: ['Existing code, or you need a method JdbcClient does not expose (some batch forms)'] },
    { label: 'JdbcTemplate', cells: ['Existing code, callbacks such as ResultSetExtractor, batch updates, and raw execute'] },
  ]}
/>

All three share the same `DataSource`, participate in the same transactions and translate
exceptions identically, so a repository can use whichever fits each method.
