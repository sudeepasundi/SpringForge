## Testing repositories against real MySQL

H2 in "MySQL mode" is not MySQL: generated columns, `ON DUPLICATE KEY UPDATE`, stored procedures,
error codes and collation all behave differently. Test against the real thing with Testcontainers.

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-testcontainers</artifactId>
    <scope>test</scope>
</dependency>
<dependency>
    <groupId>org.testcontainers</groupId>
    <artifactId>mysql</artifactId>
    <scope>test</scope>
</dependency>
```

```java
@JdbcTest                                                   // JDBC slice only
@AutoConfigureTestDatabase(replace = AutoConfigureTestDatabase.Replace.NONE)
@Testcontainers
@Import(BookRepository.class)                               // the class under test
@Sql("/books-fixture.sql")                                  // data for each test
class BookRepositoryTest {

    @Container
    @ServiceConnection                                      // wires the DataSource to the container
    static final MySQLContainer<?> MYSQL = new MySQLContainer<>("mysql:8.4");

    @Autowired BookRepository books;

    @Test
    void returns_empty_instead_of_throwing_when_nothing_matches() {
        assertThat(books.findById(987_654)).isEmpty();
    }
}
```

<Callout type="pitfall" title="Rolled-back tests can hide commit-time problems">
Because each test rolls back, anything that only happens at commit — deferred checks, after-commit
listeners — never runs. For those, annotate the test with `@Transactional(propagation = NOT_SUPPORTED)`
and clean up explicitly. See [Testcontainers](/learn/testing/testcontainers) for keeping one container
per test run so the suite stays fast.
</Callout>

HikariCP ships with the starter. The settings that matter:

  columns={['What to set', 'Why']}

<Callout type="prod">
Pool size is shared: ten application instances with twenty connections each is two hundred
connections. Check that against MySQL's `max_connections` (151 by default) before scaling out.
</Callout>

## Timeouts, at every layer

```yaml
spring:
  datasource:
    url: jdbc:mysql://db:3306/shelf?connectTimeout=3000&socketTimeout=30000
    hikari:
      connection-timeout: 3000        # waiting for a pool connection
  jdbc:
    template:
      query-timeout: 5s               # one statement
```

```java
@Transactional(timeout = 10)          // the whole transaction
public void monthlyClose() { … }
```

A query with no timeout can hold a connection — and its locks — forever. `socketTimeout` is the last
line of defence when the network, not the query, is what hangs.

## Seeing the SQL

```yaml
logging:
  level:
    org.springframework.jdbc.core.JdbcTemplate: DEBUG               # statements
    org.springframework.jdbc.core.StatementCreatorUtils: TRACE      # bound parameters
    com.zaxxer.hikari: DEBUG                                        # pool activity
```

For timings of every statement, including ones not made through Spring, wrap the `DataSource` with a
proxy such as datasource-proxy or P6Spy. On the MySQL side, the slow query log and
`EXPLAIN ANALYZE` show where the time goes.

```sql
EXPLAIN ANALYZE
SELECT * FROM loan WHERE member_id = 1 AND returned_at IS NULL;
```

## Metrics to watch

Boot publishes HikariCP metrics through Micrometer:

- `hikaricp.connections.active` and `.pending` — requests waiting for a connection mean the pool is
  too small or queries are too slow.
- `hikaricp.connections.timeout` — requests that gave up.
- `hikaricp.connections.usage` — how long connections are held.

## Security checklist

<Steps>
  <Step title="Least privilege">

The application user gets `SELECT, INSERT, UPDATE, DELETE` (and `EXECUTE` if it calls procedures) —
never DDL rights, never `root`.

  </Step>
  <Step title="Parameters, always">

Every value goes through a placeholder. Dynamic identifiers come from an allow-list.

  </Step>
  <Step title="TLS">

`sslMode=REQUIRED` (or `VERIFY_IDENTITY`) outside local development; drop `allowPublicKeyRetrieval`.

  </Step>
  <Step title="Secrets out of files">

Passwords come from the environment or a secret manager, not `application.yml`.

  </Step>
</Steps>
