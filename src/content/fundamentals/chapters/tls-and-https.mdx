## Why it matters

Without TLS, anyone on the path — the café Wi-Fi, a compromised router, another tenant on the
network — can read passwords and tokens and change responses. With TLS, they cannot. It is the reason
HTTPS is mandatory, and its handshake is a favourite interview question that ties together everything
in the previous chapters.

## How it works

### What TLS guarantees

- **Confidentiality** — traffic is encrypted.
- **Integrity** — any tampering is detected.
- **Server authentication** — the certificate proves you reached the real host (and, with mTLS, the
  client proves itself too).

It does **not** hide which IP you connect to, and the hostname is usually visible (in DNS and in the
SNI field). It does not protect data once it arrives at the server.

### The TLS 1.3 handshake

<Steps>
  <Step title="ClientHello">

The client lists the TLS versions and cipher suites it supports, the hostname it wants (**SNI**, so one
IP can serve many sites), the application protocols it can speak (**ALPN**: h2, http/1.1), and a
Diffie–Hellman **key share**.

  </Step>
  <Step title="ServerHello and key agreement">

The server picks a cipher and sends its own key share. Both sides now compute the same secret (ECDHE)
and derive keys — the secret itself never crossed the network.

  </Step>
  <Step title="The server proves who it is">

It sends its **certificate** and a **signature** over the handshake made with its private key. That
signature proves it holds the private key matching the certificate — a copied certificate is useless
without it.

  </Step>
  <Step title="The client checks everything">

Chain up to a trusted root, validity dates, hostname match. If anything fails, the connection is
aborted — this is the browser's full-page warning.

  </Step>
  <Step title="Encrypted traffic">

Both sides send Finished messages (a MAC over the whole handshake, detecting tampering), then exchange
data with fast symmetric encryption (AES-GCM or ChaCha20-Poly1305).

  </Step>
</Steps>

TLS 1.2 needed two round trips; TLS 1.3 needs one, removed weak algorithms, and always gives forward
secrecy. Resumed sessions can even send data immediately (**0-RTT**, with replay caveats).
**Disable TLS 1.0 and 1.1** — and SSL entirely.

### HTTPS

HTTPS is simply HTTP inside a TLS connection, on port 443. Related pieces:

- **HSTS** (`Strict-Transport-Security` header) tells browsers to always use HTTPS for the site, blocking
  downgrade attacks.
- **Redirect** port 80 to 443, but do not accept credentials over plain HTTP.
- **Mixed content** — an HTTPS page loading HTTP scripts — is blocked by browsers.

### Mutual TLS (mTLS)

In normal TLS only the server shows a certificate. In **mTLS**, the client presents one as well, and the
server verifies it. Used for service-to-service authentication, partner APIs, and IoT devices. A service
mesh can issue and rotate these certificates automatically.

### Certificates in operation

- Automate issuance and renewal (ACME / Let's Encrypt, cert-manager in Kubernetes, cloud certificate services).
- **Monitor expiry** — expired certificates cause some of the most embarrassing outages.
- Serve the **full chain** (server + intermediate certificates), or some clients will fail.
