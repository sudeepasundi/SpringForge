## Why it matters

"The user is logged in, so they can see the invoice" — until someone changes the invoice id in the URL
and reads another customer's. Mixing up **who you are** with **what you may do**, or storing sessions and
tokens carelessly, causes most real-world access bugs.

## How it works

### Two different questions

Authentication happens once (at login); authorization happens on **every** request, for **every**
resource.

### Authentication factors

- Something you **know** (password), **have** (phone, security key), or **are** (fingerprint).
- **MFA** combines two of these. **Passkeys** (WebAuthn) use a private key on the device — nothing
  reusable is sent to the server, so they resist phishing.

### JWT in plain words

A JSON Web Token has three Base64URL parts: `header.payload.signature`.

```json
{ "alg": "RS256", "kid": "2026-09" }
{ "sub": "42", "iss": "https://login.example.com", "aud": "orders-api",
  "exp": 1790000000, "scope": "orders:read" }
```

- The payload is **readable by anyone** — never put secrets in it.
- The signature proves the issuer created it and nobody changed it.
- The server must check **signature, `exp`, `iss` and `aud`** — and reject `alg: none`.
- Keep access tokens **short-lived** (minutes) and use **refresh tokens** (stored carefully, rotated)
  to get new ones.
- In browsers, prefer HttpOnly cookies over `localStorage` for tokens, to limit what XSS can steal.

### OAuth 2 and OpenID Connect

**OAuth 2** is about **delegated authorization**: letting an application act on your behalf without
giving it your password ("allow this app to read your calendar"). **OpenID Connect (OIDC)** adds
**authentication** on top: an **ID token** saying who the user is ("Sign in with Google").

Roles in OAuth: the **resource owner** (the user), the **client** (your app), the **authorization
server** (the identity provider: Keycloak, Auth0, Okta, Entra ID, Google) and the **resource server**
(your API).

### Authorization models

- **RBAC** (role-based): users have roles (`ADMIN`, `SUPPORT`), roles have permissions.
- **ABAC / policies**: decisions based on attributes — "a manager may approve expenses under 1,000 in
  their own department".
- **Ownership / ReBAC**: "may read this order because they own it" — the check most often forgotten.

<Compare>
  <Bad title="Authenticated is not authorized (IDOR)">

```java
@GetMapping("/invoices/{id}")
Invoice get(@PathVariable long id) {
    return invoices.findById(id).orElseThrow();   // any logged-in user can read any invoice
}
```

  </Bad>
  <Good title="Check ownership on every access">

```java
@GetMapping("/invoices/{id}")
Invoice get(@PathVariable long id, @AuthenticationPrincipal Jwt jwt) {
    return invoices.findByIdAndCustomerId(id, jwt.getSubject())
            .orElseThrow(NotFoundException::new);   // 404, not 403, to avoid revealing it exists
}
```

  </Good>
</Compare>

**Principles**: deny by default; least privilege; check on the server, never trust the UI to hide
buttons; log authorization failures.

## When you'll meet it

- **Choosing between sessions and JWTs** for a new app.
- **"Logout doesn't work"** — JWTs remain valid until they expire.
- **Integrating "Sign in with…"** — that is OIDC.
- **A service calling another service** — client-credentials tokens or mTLS.
- **Interview:** "Authentication versus authorization?", "How does OAuth work?", "Session versus JWT?"
