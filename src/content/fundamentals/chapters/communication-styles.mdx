## Why it matters

A dashboard needs live prices. A mobile app needs to know when an order ships. Two internal services
exchange thousands of calls a second. "Just use REST" works for some of these and badly for others.
Knowing how each style works on the wire lets you pick the right one.

## How it works

### Request–response over HTTP (REST)

The client asks, the server answers, the connection is free for the next request.

```http
GET /orders/981 HTTP/1.1
Accept: application/json
```

- Simple, cacheable, understood by every tool, proxy and browser.
- The server cannot start a conversation — the client must ask.

Stateful connections (SSE, WebSocket) change how you scale: each open connection is tied to one
instance, so broadcasting to a user means finding their instance — usually via a pub/sub system such
as Redis.

### gRPC

gRPC is a remote-procedure-call framework: you define services and messages in a `.proto` file, and
code is generated for the client and server. Messages are encoded with **Protocol Buffers** (compact
binary) and sent over **HTTP/2**.

```protobuf
service Inventory {
  rpc Reserve (ReserveRequest) returns (ReserveReply);
  rpc WatchStock (StockQuery) returns (stream StockLevel);   // server streaming
}
```

- Fast, strongly typed contracts, and four call types (unary, server streaming, client streaming,
  bidirectional).
- Less friendly to browsers and to reading by eye; long-lived HTTP/2 connections need layer-7 load
  balancing.

### Messaging (asynchronous)

Instead of calling a service, publish a message to a broker (Kafka, RabbitMQ) and let whoever is
interested consume it. The sender does not wait and does not need the receiver to be up. The
[queues chapter](/fundamentals/queues-and-async-processing) covers it.

### GraphQL, briefly

A single endpoint where the client describes exactly the fields it wants. Useful when many different
clients need different shapes of data; adds complexity around caching and query cost.

## When you'll meet it

- **"The dashboard hammers our API every second."** Switch polling to SSE.
- **"WebSockets drop after 60 seconds behind the load balancer."** Idle timeout — send heartbeats or raise it.
- **"Service A is down, so checkout fails."** A synchronous chain; consider asynchronous messaging.
- **Interview:** "WebSocket versus SSE versus polling?" and "When would you use gRPC over REST?"

## In a Spring and Java app

- `SseEmitter` (MVC) or `Flux` (WebFlux) for SSE; Spring's WebSocket/STOMP support; `grpc-java` or
  Spring gRPC for gRPC.
- [Communication styles](/learn/microservices-fundamentals/communication-styles) compares synchronous and
  asynchronous calls between microservices.
