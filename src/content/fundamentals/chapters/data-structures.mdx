## Why it matters

Picking the right data structure is often the whole solution: a set instead of a list turns a slow
duplicate check into an instant one; a heap turns "find the next job" from a scan into a lookup. Every
database, cache and message broker is built from these same structures.

Arrays know where element `i` is by arithmetic (`base + i × size`), and neighbouring elements sit
together in CPU cache — which is why they win in practice even for many insert-heavy workloads.

### Stacks and queues

```java
Deque<String> stack = new ArrayDeque<>();
stack.push("open (");  stack.push("open [");
stack.pop();                                  // "open [" — the most recent first

Queue<Job> queue = new ArrayDeque<>();
queue.offer(job1);  queue.offer(job2);
queue.poll();                                 // job1 — the oldest first
```

Your program's **call stack** is a stack; a message broker is a (distributed) queue.

### Hash tables

Covered in [Hashing](/fundamentals/hashing): a hash of the key picks a bucket, giving O(1) average
lookups. `HashMap` and `HashSet` in Java; dictionaries in Python; objects and `Map` in JavaScript;
Redis itself.

### Trees

A **binary search tree** keeps smaller keys to the left and larger to the right, so a search discards
half the remaining tree at each step — O(log n) **if the tree stays balanced**. Self-balancing trees
(red-black, AVL) guarantee that. **B-trees** are wide, shallow trees with many keys per node, designed
so each node fits a disk page — every relational database index is one.

### Heaps

A heap keeps the smallest (or largest) item at the top and restores that property in O(log n) after each
change. It is not fully sorted — just enough to always know the minimum.

```java
PriorityQueue<Task> tasks = new PriorityQueue<>(Comparator.comparing(Task::deadline));
tasks.add(t1); tasks.add(t2); tasks.add(t3);
tasks.poll();   // the task with the earliest deadline
```

"Top 10 of a billion items" uses a heap of size 10: O(n log 10) instead of sorting everything.

### Graphs

A graph is a set of **nodes** (vertices) connected by **edges**, which may be directed and weighted.
Stored as an **adjacency list** (each node lists its neighbours — usual for sparse graphs) or an
**adjacency matrix**.

- **BFS** (breadth-first, uses a queue): shortest path by number of hops; "friends of friends".
- **DFS** (depth-first, uses a stack or recursion): cycle detection, topological sort (build order of
  modules, Spring bean creation order).
- **Dijkstra** (uses a heap): shortest weighted path — route planning.

### Tries

A trie stores strings character by character, so all words with the same prefix share a path.
Autocomplete for "spr" walks three nodes and returns everything below.

## When you'll meet it

- **Deduplicating a large import** — a set, not `list.contains`.
- **Circular dependency errors** — the container detected a cycle in a graph (DFS).
- **Rate limiters and schedulers** — queues and heaps.
- **Interviews** — most coding questions are "pick the right structure": two-sum (hash map), valid
  parentheses (stack), top-K (heap), shortest path (BFS).
