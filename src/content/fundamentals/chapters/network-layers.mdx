## Why it matters

"The service can't reach the database." Is the cable unplugged, the IP wrong, a firewall blocking the
port, the TLS certificate expired, or the SQL wrong? Networking is built in **layers**, and debugging is
much faster when you know which layer to check first.

## How it works

### The idea of layers

Each layer solves one problem and relies on the layer below, without caring how it works. Your HTTP
client does not know whether the bytes travel over Wi-Fi or fibre; Ethernet does not know it is carrying
HTTP.

The **OSI model** has seven layers and is mostly used as vocabulary ("a layer-7 load balancer"). The
**TCP/IP model** has four and describes the internet as actually built. From ECE you already know
layers 1 and 2 well; software developers live mostly in 3, 4 and 7.

### Encapsulation

Sending data wraps it in one header per layer, like envelopes inside envelopes. The receiver unwraps
them in reverse.

- **MAC addresses** (layer 2) change at every hop — they only get the frame to the next router.
- **IP addresses** (layer 3) stay the same end to end (unless NAT rewrites them).
- **Ports** (layer 4) pick which program on the host gets the data.
- Each link has a **MTU** (maximum transmission unit, typically 1500 bytes on Ethernet); bigger
  messages are split across many packets.

### How a packet crosses the internet

Routers read the destination IP, look up the best next hop in their routing table, and forward the
packet. Each hop decrements the **TTL** field; a packet whose TTL reaches zero is dropped, which is how
`traceroute` discovers the path.

## When you'll meet it

Debug from the bottom up — each check proves the layers below it work:

<Terminal title="bottom-up debugging">
{`$ ping -c 3 db.internal
$ nc -vz db.internal 5432
Connection to db.internal port 5432 [tcp/postgresql] succeeded!
$ curl -v https://api.example.com/health`}
</Terminal>

Error messages hint at the layer too: `UnknownHostException` is DNS; `Connection refused` means the
host answered but nothing listens on that port; `Connection timed out` usually means a firewall silently
drops packets; `SSLHandshakeException` is TLS; `404` or `500` is the application.

- **Interview:** "Explain the OSI model" — describe the layers by their job and give one protocol for each.
