## Why it matters

Many learners watch course after course, understand every video, and still freeze in front of an empty
editor. This is **tutorial hell**: recognising a solution when you see it is very different from producing
one. Skill grows from **doing** — specifically, from practice that is a little too hard, with feedback.

## How it works

### Recognition is not recall

Watching someone code builds **recognition** ("yes, that makes sense"). Writing code yourself builds
**recall** ("I can produce this"). Only recall helps you at work and in interviews — and it feels harder,
slower and more frustrating, which is exactly why it works. The difficulty is the learning.

### Escaping tutorial hell

<Steps>
  <Step title="Follow one tutorial, then close it">

Finish a single good tutorial. Then rebuild the same thing **without** it. Where you get stuck is what you
actually need to learn.

</Step>
  <Step title="Change the project">

Add a feature the tutorial didn't have: search, a new entity, authentication, a different database.

</Step>
  <Step title="Build something you want">

A tool for yourself, a clone of an app you use, a project for a friend. Real requirements force real
problems.

</Step>
  <Step title="Get feedback">

Tests, a code review from someone more experienced, or comparing with how an established open-source
project solved the same problem.

</Step>
</Steps>

### Practising problem solving

- Solve problems **by pattern**: several two-pointer problems in a row, then several sliding-window ones.
  Patterns stick when you see them repeatedly ([Part 2](/craft/hash-maps-and-sets)).
- Use a **timer** (25–45 minutes). If stuck at the end, read a hint — not the solution — and try again.
- After reading a solution, **close it and write it yourself** the next day.
- Keep a **mistake log**: what went wrong and why. Review it weekly.

### Spaced repetition

You forget quickly unless you revisit. Revisit a topic after a day, then a few days, then a couple of
weeks. Flashcards (Anki) work well for facts — API names, SQL syntax, complexity classes — and
re-solving old problems works for skills.

### Measure progress honestly

- Can you build it **without** looking anything up?
- Can you explain **why** it works, and when it wouldn't?
- Did last month's hard problems become this month's easy ones?
