## Why it matters

Some teams put business logic in stored procedures; others forbid them. You will meet both, and you
will certainly need to create database users with the right privileges — an application that connects
as the database owner is one SQL injection away from `DROP TABLE`. SQLite has neither procedures nor
users, so this chapter's examples are MySQL and PostgreSQL, shown as code.

**MySQL:**

```sql
DELIMITER //
CREATE PROCEDURE checkout_book(IN p_book BIGINT, IN p_member BIGINT, OUT p_loan BIGINT)
BEGIN
  DECLARE left_ INT;
  SELECT copies_available INTO left_ FROM book WHERE id = p_book FOR UPDATE;
  IF left_ < 1 THEN
    SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'No copies left';
  END IF;
  UPDATE book SET copies_available = copies_available - 1 WHERE id = p_book;
  INSERT INTO loan (book_id, member_id, borrowed_on) VALUES (p_book, p_member, CURRENT_DATE);
  SET p_loan = LAST_INSERT_ID();
END //
DELIMITER ;

CALL checkout_book(42, 7, @loan);
SELECT @loan;
```

**PostgreSQL** (PL/pgSQL):

```sql
CREATE FUNCTION order_total(p_order bigint) RETURNS numeric
LANGUAGE sql STABLE AS $$
  SELECT COALESCE(SUM(quantity * unit_price), 0) FROM order_item WHERE order_id = p_order;
$$;

SELECT id, order_total(id) FROM orders;

CREATE PROCEDURE archive_orders(p_before date)
LANGUAGE plpgsql AS $$
BEGIN
  INSERT INTO orders_archive SELECT * FROM orders WHERE ordered_at < p_before;
  DELETE FROM orders WHERE ordered_at < p_before;
END;
$$;

CALL archive_orders('2025-01-01');
```

### Should logic live in the database?

/>

The common modern position: rules the data must always obey go in **constraints**; heavy set-based
work goes in **SQL** (often plain statements from the application); **workflows** go in the application.
Procedures are a tool, not a default.

### Users, roles and privileges

Grant each application **only** what it needs — the principle of least privilege.

```sql
-- PostgreSQL
CREATE ROLE shop_app LOGIN PASSWORD '…';               -- use a secrets manager, not a literal
GRANT CONNECT ON DATABASE shop TO shop_app;
GRANT USAGE ON SCHEMA public TO shop_app;
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO shop_app;
GRANT USAGE ON ALL SEQUENCES IN SCHEMA public TO shop_app;

CREATE ROLE reporting;                                  -- a group role
GRANT SELECT ON order_summary TO reporting;             -- a view, not the tables
GRANT reporting TO analyst_anna;

REVOKE DELETE ON orders FROM shop_app;

-- MySQL
CREATE USER 'shop_app'@'%' IDENTIFIED BY '…';
GRANT SELECT, INSERT, UPDATE, DELETE ON shop.* TO 'shop_app'@'%';
GRANT EXECUTE ON PROCEDURE shop.checkout_book TO 'shop_app'@'%';
```

multi-tenant systems.
