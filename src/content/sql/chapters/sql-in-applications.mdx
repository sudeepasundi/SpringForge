## Why it matters

Most SQL in production is sent by application code, and most database incidents start there: an
injection hole, a loop issuing a thousand queries, a `SELECT *` pulling megabytes nobody reads, a query
that was fast on test data. This chapter collects the habits that keep SQL from applications safe and
fast.

## How it works

### Always use parameters

<Compare>
  <Bad title="String building — SQL injection">

```java
String sql = "SELECT * FROM customer WHERE email = '" + email + "'";
// email = ' OR '1'='1   → every customer
```

  </Bad>
  <Good title="Placeholders — the value is always data">

```java
jdbc.query("SELECT id, name FROM customer WHERE email = ?", mapper, email);
```

  </Good>
</Compare>

Here is what the injected string does to the query:

<SqlPlayground

SELECT id, name, email FROM customer WHERE email = '' OR '1'='1';`}
/>

Parameters cannot be used for identifiers (table or column names, sort direction). For those, **allow-list**
the value in code: `Map.of("price", "price", "name", "name").get(sortParam)`.

### Avoid N+1 queries

<Compare>
  <Bad title="One query per row">

```java
List<Order> orders = jdbc.query("SELECT * FROM orders WHERE customer_id = ?", …);
for (Order o : orders) {
    o.setItems(jdbc.query("SELECT * FROM order_item WHERE order_id = ?", …, o.id()));  // N more
}
```

  </Bad>
  <Good title="One query for all of them">

```sql
SELECT oi.* FROM order_item oi
WHERE oi.order_id IN (SELECT id FROM orders WHERE customer_id = ?);
-- or a join, grouped in the application
```

  </Good>
</Compare>

Each round trip costs about half a millisecond or more; 1,000 of them is a slow page no index can fix.

### Page and stream large results

Never load an unbounded result into memory. Use `LIMIT` with keyset pagination for APIs
([Sorting and Pagination](/sql/sorting-and-pagination)), and streaming cursors for exports
([JDBC: batching and large results](/jdbc/batching-and-large-results)).

### Batch writes

<SqlPlayground
  dataset="shop"
  title="One statement instead of many round trips"
  query={`INSERT INTO category (name, parent_id) VALUES
  ('Board Games', NULL),
  ('Puzzles', NULL),
  ('Toys', NULL);

SELECT id, name FROM category ORDER BY id DESC LIMIT 3;`}
/>

From Java, JDBC batching (`addBatch`/`executeBatch`, `JdbcTemplate.batchUpdate`) sends many parameter
sets in one round trip; MySQL needs `rewriteBatchedStatements=true` to turn them into multi-row inserts.

<SqlPlayground
  dataset="shop"
  title="DISTINCT hiding a join problem"
  query={`-- "customers who bought audio" — DISTINCT hides that the join repeats customers
SELECT DISTINCT c.name
FROM customer c
JOIN orders o      ON o.customer_id = c.id
JOIN order_item oi ON oi.order_id = o.id
JOIN product p     ON p.id = oi.product_id
WHERE p.category_id = 6;

-- clearer, and stops at the first match per customer
SELECT c.name FROM customer c
WHERE EXISTS (
  SELECT 1 FROM orders o
  JOIN order_item oi ON oi.order_id = o.id
  JOIN product p     ON p.id = oi.product_id
  WHERE o.customer_id = c.id AND p.category_id = 6
);`}
/>

### Observe what your application sends

- Log SQL in development (`spring.jpa.show-sql`, or the JDBC loggers) and count the statements per request.
- In production, use `pg_stat_statements` (PostgreSQL) or the Performance Schema (MySQL) to find the
  queries that take the most **total** time — often a fast query run millions of times.
- Put database migrations in version control ([Flyway](/learn/data/migrations)).

## Exercises

<SqlExercise
  dataset="shop"
  prompt="Replace a per-order loop: in one query, return order_id and the number of items (sum of quantity, as items) for every order of customer 2."
  solution={`SELECT oi.order_id, SUM(oi.quantity) AS items
FROM order_item oi
JOIN orders o ON o.id = oi.order_id
WHERE o.customer_id = 2
GROUP BY oi.order_id;`}
  hint="Join and GROUP BY order_id instead of one query per order."
/>

<SqlExercise
  dataset="shop"
  prompt="Return the names of customers who have reviewed at least one product, without DISTINCT (use EXISTS)."
  solution={`SELECT c.name FROM customer c
WHERE EXISTS (SELECT 1 FROM review r WHERE r.customer_id = c.id);`}
/>
