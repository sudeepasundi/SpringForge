## The defaults, in one line

`@Transactional` with no attributes means: **REQUIRED** propagation, the database's default isolation,
no timeout, not read-only, and **rollback only on unchecked exceptions**.

```java
@Transactional                          // REQUIRED, DEFAULT isolation
public Order place(Cart cart) { … }

@Transactional(readOnly = true)         // queries
public Page<Order> history(Pageable page) { … }

@Transactional(rollbackFor = Exception.class, timeout = 5)
public void importFile(Path file) throws IOException { … }
```

<Callout type="pitfall" title="REQUIRES_NEW takes a second connection">
The outer transaction's connection is held while the inner one runs on another. Under load, a pool
of ten connections with ten requests each needing two deadlocks the pool — every request holds one
connection and waits forever for its second.
</Callout>

<Callout type="pitfall" title="An inner REQUIRED method that throws poisons the outer transaction">
The inner method joined the outer transaction, so its exception marks the **whole** transaction
rollback-only. Catching the exception in the outer method does not help: the commit then fails with
`UnexpectedRollbackException`.
</Callout>

## Isolation

What a transaction can see of other transactions' work.

<DecisionTable
  columns={['Dirty read', 'Non-repeatable read', 'Phantom read']}
  rows={[
    { label: 'READ_UNCOMMITTED', verdict: 'bad', cells: ['Possible', 'Possible', 'Possible'] },
    { label: 'READ_COMMITTED', verdict: 'good', cells: ['Prevented', 'Possible', 'Possible'] },
    { label: 'REPEATABLE_READ', verdict: 'mixed', cells: ['Prevented', 'Prevented', 'Possible (prevented in Postgres)'] },
    { label: 'SERIALIZABLE', verdict: 'mixed', cells: ['Prevented', 'Prevented', 'Prevented — with serialisation failures to retry'] },
  ]}
/>

- **Dirty read** — seeing another transaction's uncommitted change.
- **Non-repeatable read** — reading the same row twice and getting different values.
- **Phantom read** — running the same query twice and getting different rows.

`DEFAULT` means the database's own default: **READ_COMMITTED** for Postgres, Oracle and SQL Server,
**REPEATABLE_READ** for MySQL InnoDB. For lost updates, prefer `@Version` optimistic locking over
raising isolation.

## Where transactions silently do not apply

`@Transactional` works through a proxy, so it is **ignored** on:

- calls from another method of the **same class** (self-invocation);
- **private** methods, and final methods on CGLIB proxies;
- objects you created with `new`;
- code running in `@PostConstruct`.

See [Proxies & AOP Gotchas](/basics/proxies-and-aop-gotchas) for how to detect and fix each.

## Doing something after commit

```java
@TransactionalEventListener                 // phase = AFTER_COMMIT
void onPlaced(OrderPlaced event) {
    emails.sendConfirmation(event.orderId());   // never sent for a rolled-back order
}
```

For a side effect that must never be lost, publish through an
[outbox](/learn/event-driven/outbox-pattern) instead — an after-commit listener dies with the process.
