## The scopes

<DecisionTable
  columns={['Instances', 'Lives for', 'Typical use']}
  rows={[
    { label: 'singleton', verdict: 'good', cells: ['One per container', 'The application', 'Almost everything — services, repositories, clients'] },
    { label: 'prototype', verdict: 'mixed', cells: ['One per injection or lookup', 'Whoever holds it', 'Stateful helpers with a short, single use'] },
    { label: 'request', cells: ['One per HTTP request', 'The request', 'Per-request context: tenant, correlation data'] },
    { label: 'session', cells: ['One per HTTP session', 'The session', 'Server-side session state — rare in stateless APIs'] },
    { label: 'application', cells: ['One per ServletContext', 'The web application', 'Almost never different from singleton'] },
  ]}

Singletons are shared by every thread, so **a singleton must be stateless or thread-safe**. A mutable
field on a `@Service` is a race condition waiting for traffic.

<Compare>
  <Bad title="State on a singleton">

```java
@Service
public class ReportService {
    private String currentTenant;          // shared by every request

    public Report build(String tenant) {
        this.currentTenant = tenant;       // another thread overwrites it
        return render();
    }
}
```

  </Bad>
  <Good title="State stays on the stack">

```java
@Service
public class ReportService {
    public Report build(String tenant) {
        return render(tenant);             // passed, never stored
    }
}
```

  </Good>
</Compare>

## The prototype-into-singleton trap

A singleton is created once, so its dependencies are injected once. Inject a prototype and the
singleton keeps **that one instance forever** — the prototype scope silently stops meaning anything.

<DecisionTable
  columns={['How', 'Choose it when']}
  rows={[
    { label: 'ObjectProvider<T>', verdict: 'good', cells: ['provider.getObject() creates a new instance per call', 'The default fix — explicit and testable'] },
    { label: 'Scoped proxy', verdict: 'good', cells: ['proxyMode = TARGET_CLASS injects a proxy that resolves per call', 'Request- and session-scoped beans injected into singletons'] },
    { label: '@Lookup method', cells: ['Spring overrides an abstract method to return a fresh bean', 'Legacy code; less obvious to readers'] },
  ]}
/>

```java
@Service
public class ImportService {
    private final ObjectProvider<CsvParser> parsers;   // CsvParser is @Scope("prototype")

    public ImportService(ObjectProvider<CsvParser> parsers) { this.parsers = parsers; }

    public void importFile(Path file) {
        CsvParser parser = parsers.getObject();         // a fresh one every time
        parser.parse(file);
    }
}
```

<Callout type="pitfall" title="Request scope without a proxy fails at startup">
A request-scoped bean injected directly into a singleton has no request to belong to when the
singleton is created, so the context fails to start with a "scope 'request' is not active" error.
`proxyMode = ScopedProxyMode.TARGET_CLASS` injects a proxy that finds the current request's instance
on every call.
</Callout>

## The lifecycle

Three consequences worth remembering:

1. **`@PostConstruct` runs before proxies exist.** Calling your own `@Transactional` method from it
   runs without a transaction.
2. **Prototype beans are never destroyed by the container.** `@PreDestroy` does not run for them —
   whoever asked for the instance owns its cleanup.
3. **`@PreDestroy` only runs on graceful shutdown.** A `kill -9` or an OOM kill skips it.

<Callout type="tip" title="Need the whole application to be ready?">
`@PostConstruct` runs while the context is still starting. For work that needs every bean ready —
warming a cache from the database, registering with an external system — listen for
`ApplicationReadyEvent` instead.

```java
@EventListener(ApplicationReadyEvent.class)
void warmUp() { cache.preload(); }
```
</Callout>
