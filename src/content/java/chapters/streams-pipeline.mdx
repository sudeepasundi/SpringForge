## What a stream is

A **stream** is a sequence of elements you process with a pipeline of operations. It is not a
collection: it stores nothing, it can be traversed **once**, and it does no work until you ask for a
result.

<Compare>
  <Bad title="Imperative: say how">

```java
List<String> result = new ArrayList<>();
for (Order order : orders) {
    if (order.total() > 100) {
        String name = order.customer().toUpperCase();
        if (!result.contains(name)) {
            result.add(name);
        }
    }
}
Collections.sort(result);
```

  </Bad>
  <Good title="Declarative: say what">

```java
List<String> result = orders.stream()
        .filter(o -> o.total() > 100)
        .map(o -> o.customer().toUpperCase())
        .distinct()
        .sorted()
        .toList();
```

Each line is one step, and the steps read in the order they happen.

  </Good>
</Compare>

### Sources

```java
list.stream()                       // any Collection
Arrays.stream(array)                // arrays (and IntStream for int[])
Stream.of("a", "b", "c")            // fixed values
Stream.iterate(1, n -> n * 2)       // infinite: 1, 2, 4, 8, …
Stream.iterate(1, n -> n < 100, n -> n * 2)   // Java 9: with a stop condition
Stream.generate(UUID::randomUUID)   // infinite, from a Supplier
IntStream.range(0, 10)              // 0..9;  rangeClosed(1, 10) is 1..10
Files.lines(path)                   // lines of a file — must be closed
"text".chars()                      // an IntStream of characters
map.entrySet().stream()             // a map's entries
```

## Laziness

Intermediate operations only **describe** work. Nothing happens until a terminal operation runs, and
then elements flow through the whole pipeline **one at a time** — not stage by stage.

```java
Stream.of("one", "two", "three", "four")
        .filter(s -> { System.out.println("filter " + s); return s.length() > 3; })
        .map(s -> { System.out.println("map " + s); return s.toUpperCase(); })
        .findFirst();

// filter one
// filter two
// filter three
// map three          ← found; "four" is never even looked at
```

Two consequences:

- **Short-circuiting** operations (`findFirst`, `anyMatch`, `limit`) stop early, which makes infinite
  sources usable: `Stream.iterate(1, n -> n + 1).filter(isPrime).limit(10).toList()`.
- A pipeline with **no terminal operation does nothing**. `list.stream().peek(System.out::println);` prints nothing.

<Callout type="tip" title="Order the cheap, selective steps first">
`filter` before `map` means fewer elements get transformed. `sorted` after `filter` sorts less. The
result is the same; the work is not.
</Callout>

## `map` versus `flatMap`

```java
List<List<String>> nested = List.of(List.of("a", "b"), List.of("c"));

nested.stream().map(List::stream);        // Stream<Stream<String>> — not what you want
nested.stream().flatMap(List::stream);    // Stream<String>: a, b, c

orders.stream()
      .flatMap(order -> order.lines().stream())      // every line of every order
      .map(OrderLine::sku)
      .distinct()
      .toList();
```

`flatMap` is also how you drop empty `Optional`s: `.flatMap(Optional::stream)`.

## Primitive streams

`IntStream`, `LongStream` and `DoubleStream` avoid boxing and add numeric operations.

```java
int total = orders.stream().mapToInt(Order::quantity).sum();
OptionalDouble avg = orders.stream().mapToInt(Order::quantity).average();
IntSummaryStatistics stats = orders.stream().mapToInt(Order::quantity).summaryStatistics();
stats.getMin(); stats.getMax(); stats.getAverage(); stats.getCount();

List<Integer> squares = IntStream.rangeClosed(1, 5).map(i -> i * i).boxed().toList();
```

## `toList()` versus `collect(Collectors.toList())`

`stream.toList()` (Java 16) returns an **unmodifiable** list. `Collectors.toList()` returns a list with
no guarantees — today an `ArrayList` you can modify. If code later calls `add` on the result, switching
between the two changes behaviour. Prefer `toList()` and copy into an `ArrayList` when you really need
to mutate.
