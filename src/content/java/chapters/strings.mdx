## Strings are immutable

A `String` never changes. Every "modifying" method returns a **new** string.

```java
String s = "hello";
s.toUpperCase();          // returns "HELLO" — and it is thrown away
System.out.println(s);    // hello
s = s.toUpperCase();      // now s points at the new string
```

Why immutable?

- **Safe to share** — the same string can be used by many objects and threads with no copying or locking.
- **Safe as a key** — its `hashCode` never changes, and `String` caches it after the first call.
- **Secure** — a file path or class name checked once cannot be altered afterwards.
- **Poolable** — identical literals can be the same object (below).

## The string pool

String **literals** are interned: the JVM keeps one shared instance per distinct literal in the
**string pool** (on the heap since Java 7).

```java
String a = "java";
String b = "java";
String c = new String("java");   // forces a new object — almost never what you want
String d = c.intern();           // the pooled instance

a == b;          // true  — the same pooled object
a == c;          // false — c is a separate object
a == d;          // true
a.equals(c);     // true  — always compare strings with equals
```

Compile-time constants are folded and pooled too: `"ja" + "va" == "java"` is `true`. Concatenation
of variables at run time is not: `x + y == "java"` is `false` even when the text matches.

<Callout type="pitfall" title="Always use equals for strings">
`==` sometimes "works" because of pooling, which is exactly what makes it dangerous — it breaks as soon
as one string comes from a file, a request or a concatenation. Use `equals`, `equalsIgnoreCase`, or
`Objects.equals(a, b)` when either may be null. Put the literal first to avoid a
`NullPointerException`: `"yes".equals(answer)`.
</Callout>

## Building strings

Because strings are immutable, concatenating in a loop creates a new string every time.

<Compare>
  <Bad title="Concatenation in a loop — quadratic">

```java
String report = "";
for (Row row : rows) {
    report += row.name() + ": " + row.total() + "\n";   // copies everything so far, each time
}
```

  </Bad>
  <Good title="One StringBuilder">

```java
StringBuilder report = new StringBuilder();
for (Row row : rows) {
    report.append(row.name()).append(": ").append(row.total()).append('\n');
}
return report.toString();
```

  </Good>
</Compare>

A single expression like `"Hello " + name + "!"` is fine — the compiler optimises it (since Java 9
via `invokedynamic` string concatenation). Loops are where it matters.

Other ways to assemble text:

```java
String.join(", ", names);                             // Ada, Linus
names.stream().collect(Collectors.joining(", "));
"%s owes %.2f".formatted(name, amount);               // Java 15; same as String.format
String.format(Locale.ROOT, "%,d", 1234567);           // 1,234,567
```

## Useful methods

```java
s.length(); s.charAt(0); s.isEmpty();
s.isBlank();                        // Java 11: empty or only whitespace
s.strip();                          // Java 11: Unicode-aware; trim() only removes chars ≤ U+0020
s.stripLeading(); s.stripTrailing();
s.repeat(3);                        // Java 11
s.lines();                          // Java 11: Stream<String>
s.indent(4);                        // Java 12
s.chars();                          // IntStream of chars
s.substring(1, 4);                  // from index 1 up to (not including) 4
s.indexOf("x"); s.lastIndexOf("x"); s.contains("x");
s.startsWith("pre"); s.endsWith(".csv");
s.replace("a", "b");                // literal
s.replaceAll("\\s+", " ");          // regex
s.split(",");                       // regex! split(".") returns an empty array — use split("\\.")
s.toLowerCase(Locale.ROOT);         // pass a Locale: Turkish 'I' lower-cases differently
String.valueOf(42); Integer.parseInt("42");
```

## Text blocks

Java 15 added multi-line string literals. Indentation is stripped based on the closing delimiter.

```java
String json = """
        {
          "name": "%s",
          "active": true
        }
        """.formatted(name);
```

- The content starts on the line after the opening `"""`.
- A trailing `\` joins a line with the next; `\s` keeps a trailing space.
- The result uses `\n` line endings whatever the source file uses.

## Strings and memory

- Since Java 9, **compact strings** store Latin-1 text in one byte per character instead of two.
- `substring` copies (since Java 7u6), so a small substring no longer keeps a huge original alive.
- G1 can **deduplicate** equal strings in the heap (`-XX:+UseStringDeduplication`).
- Passwords belong in a `char[]` you can clear, not a `String` that lingers until garbage collection.
