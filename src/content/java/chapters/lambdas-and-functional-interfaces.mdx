## From anonymous classes to lambdas

Before Java 8, passing behaviour meant an anonymous class:

```java
Collections.sort(names, new Comparator<String>() {
    @Override
    public int compare(String a, String b) {
        return a.length() - b.length();
    }
});
```

A **lambda expression** is a short way to write the one method of a functional interface:

```java
names.sort((a, b) -> Integer.compare(a.length(), b.length()));
```

Same behaviour, a fraction of the noise. The compiler infers that the lambda is a
`Comparator<String>` from where it is used — this is its **target type**.

## Syntax

```java
() -> 42                                   // no parameters
x -> x * 2                                 // one parameter: parentheses optional
(x, y) -> x + y                            // several parameters
(String s, int n) -> s.repeat(n)           // explicit types — all or none
(var s, var n) -> s.repeat(n)              // var (Java 11), lets you add annotations
(a, b) -> {                                // a block body needs return
    int sum = a + b;
    return sum * sum;
}
```

A lambda has no name, no type of its own, and cannot be used where no functional interface is
expected: `var f = x -> x;` does not compile.

## Functional interfaces

A functional interface has **exactly one abstract method**. Any such interface can be a lambda's
target — `Runnable`, `Comparator`, `Callable`, your own `Categorizer`. `@FunctionalInterface` makes the
compiler check the rule.

For primitives there are boxing-free variants — `IntPredicate`, `IntFunction<R>`, `ToIntFunction<T>`,
`IntUnaryOperator`, `IntBinaryOperator`, `LongSupplier`, `DoubleConsumer` and so on. Use them in hot
code: `Function<Integer, Integer>` boxes every value.

### Composing functions

The standard interfaces have default methods that build new functions from old ones:

```java
Function<String, String> trim = String::trim;
Function<String, Integer> length = String::length;
Function<String, Integer> trimmedLength = trim.andThen(length);   // trim first, then length

Predicate<String> blank = String::isBlank;
Predicate<String> longer = s -> s.length() > 10;
Predicate<String> interesting = blank.negate().and(longer);
Predicate<String> notBlank = Predicate.not(String::isBlank);       // Java 11

Comparator<Person> byAge = Comparator.comparing(Person::age);
Comparator<Person> oldestFirst = byAge.reversed();

UnaryOperator<String> identity = UnaryOperator.identity();
```

## Capturing variables

A lambda can use local variables from the enclosing method, but only if they are **effectively
final** — never assigned after initialisation.

<Compare>
  <Bad title="Modifying a captured variable">

```java
int total = 0;
items.forEach(item -> total += item.price());   // does not compile
```

The lambda may run later or on another thread; a captured copy of `total` could never be updated
safely, so Java forbids it.

  </Bad>
  <Good title="Compute a value instead">

```java
int total = items.stream().mapToInt(Item::price).sum();
```

Fields and array elements *can* be modified from a lambda — which is exactly why doing so is a
common source of race conditions. Prefer returning a result.

  </Good>
</Compare>

## Exceptions in lambdas

The standard functional interfaces declare no checked exceptions, so a lambda that calls
`Files.readString` will not compile inside `map`. Options:

```java
// 1. Handle it inside the lambda
paths.stream().map(p -> {
    try {
        return Files.readString(p);
    } catch (IOException e) {
        throw new UncheckedIOException(e);   // wrap in the matching unchecked type
    }
});

// 2. Extract a method that does the wrapping, then use a method reference
paths.stream().map(this::readOrThrow);
```

Tally's `StatementImporter` does the same with `CompletionException` inside a `Supplier`.
