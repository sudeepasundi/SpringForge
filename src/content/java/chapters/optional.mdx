## What `Optional` is for

`Optional<T>` is a container that holds **one value or nothing**. Its job is narrow: to make "there
might be no result" part of a method's **return type**, so the caller cannot forget.

```java
User findUser(long id);              // may return null — nothing tells the caller
Optional<User> findUser(long id);    // the signature says "maybe"
```

## Creating

```java
Optional.of(value)            // value must not be null — NullPointerException otherwise
Optional.ofNullable(value)    // empty if value is null
Optional.empty()              // nothing
```

  <Bad title="orElse always evaluates its argument">

```java

```

  </Bad>

```java
User user = cache.find(id)
        .orElseGet(() -> database.load(id));   // only on a miss
```

## Transforming without unwrapping

```java
Optional<String> city = findUser(id)
        .map(User::address)                 // Optional<Address>, empty if address() returns null
        .map(Address::city);                // Optional<String>

Optional<Account> account = findUser(id)
        .flatMap(user -> accounts.findFor(user));   // the function itself returns Optional

Optional<User> adult = findUser(id)
        .filter(u -> u.age() >= 18);        // empty if the condition fails

Optional<User> any = cache.find(id)
        .or(() -> database.find(id));       // Java 9: another Optional as the fallback

Stream<User> users = findUser(id).stream(); // Java 9: zero or one element
```

`map` wraps the result for you (and turns a `null` result into empty); `flatMap` is for functions that
already return an `Optional`, so you do not get `Optional<Optional<T>>`.

<Compare>
  <Bad title="Optional used like a null check">

```java
Optional<User> user = findUser(id);
if (user.isPresent()) {
    Address address = user.get().address();
    if (address != null) {
        return address.city();
    }
}
return "unknown";
```

  </Bad>
  <Good title="A pipeline">

```java
return findUser(id)
        .map(User::address)
        .map(Address::city)
        .orElse("unknown");
```

  </Good>
</Compare>

<Callout type="pitfall" title="Never return null from an Optional method">
A method declared to return `Optional` must never return `null` — callers will call `.map` on it and
get a `NullPointerException`, which is exactly what `Optional` was supposed to prevent.
</Callout>

## In Spring

Spring Data repositories return `Optional<T>` from `findById`. The idiomatic controller-side pattern:

```java
Order order = orders.findById(id)
        .orElseThrow(() -> new OrderNotFoundException(id));   // mapped to a 404 by an exception handler
```
