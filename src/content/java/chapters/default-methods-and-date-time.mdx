## Default methods

Before Java 8, adding a method to a published interface broke every implementation. Default methods
let `Collection` gain `stream()`, `removeIf` and `forEach` without breaking a single existing class.

```java
public interface Collection<E> {
    default boolean removeIf(Predicate<? super E> filter) {
        boolean removed = false;
        Iterator<E> it = iterator();
        while (it.hasNext()) {
            if (filter.test(it.next())) { it.remove(); removed = true; }
        }
        return removed;
    }
}
```

Implementations may override a default with something faster (`ArrayList` does). The conflict rules
are in the abstraction chapter.

### The new `Map` methods

These replace a lot of get-check-put code:

```java
counts.merge(word, 1, Integer::sum);                         // add, or combine with the old value
map.computeIfAbsent(key, k -> new ArrayList<>()).add(value); // multimap in one line
map.computeIfPresent(key, (k, v) -> v.isEmpty() ? null : v); // returning null removes the entry
map.getOrDefault(key, 0);
map.putIfAbsent(key, value);
map.forEach((k, v) -> System.out.println(k + " = " + v));
map.replaceAll((k, v) -> v.trim());
list.removeIf(String::isBlank);
list.replaceAll(String::toUpperCase);
```

## `java.time`

The old `java.util.Date` and `Calendar` are mutable, not thread-safe, zero-based for months, and mix
up instants with calendar dates. `java.time` (JSR-310) fixes all of that. Every class is **immutable
and thread-safe**.

<Callout type="tip" title="A simple rule">
Store and transmit **`Instant`** (in UTC). Convert to a **`ZonedDateTime`** only at the edge, to show a
user their local time. Use **`LocalDate`** when the concept really has no time — a birthday is the same
date in every zone.
</Callout>

### Creating and computing

```java
LocalDate today = LocalDate.now(clock);              // pass a Clock so tests can fix "now"
LocalDate due = LocalDate.of(2026, Month.SEPTEMBER, 30);
LocalDate next = due.plusMonths(1).withDayOfMonth(1);   // every call returns a new object

YearMonth month = YearMonth.from(due);
LocalDate first = month.atDay(1);
LocalDate last = month.atEndOfMonth();
int days = month.lengthOfMonth();

Instant start = Instant.now();
Duration elapsed = Duration.between(start, Instant.now());
Period age = Period.between(birthday, today);        // P34Y2M11D
long daysLeft = ChronoUnit.DAYS.between(today, due);

ZonedDateTime paris = Instant.now().atZone(ZoneId.of("Europe/Paris"));
ZonedDateTime tokyo = paris.withZoneSameInstant(ZoneId.of("Asia/Tokyo"));

LocalDate nextFriday = today.with(TemporalAdjusters.next(DayOfWeek.FRIDAY));
```

<Callout type="pitfall" title="Duration versus Period across daylight saving">
`zoned.plus(Duration.ofDays(1))` adds exactly 24 hours; `zoned.plus(Period.ofDays(1))` adds one
calendar day. On the night the clocks change they give different wall-clock times.
</Callout>

### Formatting and parsing

```java
DateTimeFormatter uk = DateTimeFormatter.ofPattern("dd/MM/yyyy");
LocalDate parsed = LocalDate.parse("30/09/2026", uk);   // DateTimeParseException if it does not match
String text = parsed.format(DateTimeFormatter.ISO_LOCAL_DATE);   // 2026-09-30

Instant.parse("2026-09-30T10:15:30Z");   // ISO-8601 parsing needs no formatter
```

`DateTimeFormatter` is immutable and thread-safe — keep it in a `static final` constant. (Its
predecessor, `SimpleDateFormat`, was neither, and sharing one between threads corrupted dates.)

Pattern letters are case-sensitive: `MM` is month, `mm` is minute; `yyyy` is year-of-era, `YYYY` is
week-based year and gives wrong dates around New Year.

### Testing with `Clock`

Code that calls `LocalDate.now()` directly is hard to test. Inject a `java.time.Clock` instead:

```java
class InvoiceService {
    private final Clock clock;
    InvoiceService(Clock clock) { this.clock = clock; }
    boolean isOverdue(Invoice i) { return i.due().isBefore(LocalDate.now(clock)); }
}

new InvoiceService(Clock.fixed(Instant.parse("2026-10-01T00:00:00Z"), ZoneOffset.UTC));
```

## `CompletableFuture`, briefly

Java 8 also added `CompletableFuture`: a future you can **compose** instead of blocking on.

```java
CompletableFuture<Report> report = CompletableFuture
        .supplyAsync(() -> loadOrders(customerId))          // run in the background
        .thenApply(orders -> summarise(orders))              // transform when done
        .thenCombine(loadProfileAsync(customerId), Report::new)   // join with another future
        .exceptionally(ex -> Report.empty());                // recover from failure
```
