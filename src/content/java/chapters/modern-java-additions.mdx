## Immutable collection factories (Java 9–10)

```java
List<String> list = List.of("a", "b");
Set<String> set = Set.of("a", "b");
Map<String, Integer> map = Map.of("a", 1, "b", 2);          // up to 10 pairs
Map<String, Integer> big = Map.ofEntries(Map.entry("a", 1), Map.entry("b", 2));
List<String> copy = List.copyOf(someCollection);             // Java 10
```

They are truly immutable, reject `null`, and `Set.of` / `Map.of` reject duplicates. Their iteration
order is not specified.

## `Stream.toList()` and `mapMulti` (Java 16)

```java
List<String> names = people.stream().map(Person::name).toList();   // unmodifiable

// mapMulti: push zero or more results, without creating a stream per element
List<Integer> evensTwice = numbers.stream()
        .<Integer>mapMulti((n, sink) -> {
            if (n % 2 == 0) { sink.accept(n); sink.accept(n); }
        })
        .toList();
```

## Sequenced collections (Java 21)

Before 21, getting the last element was different for every collection type: `list.get(size - 1)`,
`deque.getLast()`, `sortedSet.last()`, and nothing at all for `LinkedHashSet`. Java 21 added common
interfaces for collections with a defined order.

```java
interface SequencedCollection<E> extends Collection<E> {
    E getFirst();  E getLast();
    void addFirst(E e);  void addLast(E e);
    E removeFirst();  E removeLast();
    SequencedCollection<E> reversed();
}
```

`List`, `Deque`, `LinkedHashSet` and `SortedSet` implement it; `SequencedMap` adds `firstEntry()`,
`lastEntry()`, `pollFirstEntry()` and `reversed()` to `LinkedHashMap` and `SortedMap`.

```java
list.getLast();
linkedHashSet.getFirst();
linkedHashMap.lastEntry();
for (var item : list.reversed()) { … }   // a reversed view, not a copy
```

## The HTTP client (Java 11)

A modern HTTP/1.1 and HTTP/2 client in the JDK, with synchronous and asynchronous APIs.

```java
HttpClient client = HttpClient.newBuilder()
        .connectTimeout(Duration.ofSeconds(2))
        .build();

HttpRequest request = HttpRequest.newBuilder(URI.create("https://api.example.com/rates"))
        .timeout(Duration.ofSeconds(5))
        .header("Accept", "application/json")
        .GET()
        .build();

HttpResponse<String> response = client.send(request, HttpResponse.BodyHandlers.ofString());

client.sendAsync(request, HttpResponse.BodyHandlers.ofString())
        .thenApply(HttpResponse::body)
        .thenAccept(System.out::println);
```

In a Spring application you would normally use `RestClient` or `WebClient`, which can use this client
underneath.

## The module system (Java 9), briefly

A **module** groups packages and states, in `module-info.java`, what it needs and what it exposes.

```java
module dev.springforge.tally.core {
    requires java.logging;
    exports dev.springforge.tally.money;        // other modules may use these packages
    exports dev.springforge.tally.report;
    // packages not exported are inaccessible, even if their classes are public
}
```

What it gives you: **reliable configuration** (missing modules fail at start-up, not mid-run),
**strong encapsulation** (public is no longer public to everyone), and **smaller runtimes** via
`jlink`.

In practice, most application code — including typical Spring Boot applications — still runs on the
**classpath** without `module-info.java`. The part that affects everyone is that the JDK's own
internals are now encapsulated (`sun.*` and `com.sun.*` packages), which is why old libraries sometimes need
`--add-opens` flags.

## Unnamed variables (Java 22)

When a pattern or lambda parameter must exist but is not used, `_` says so:

```java
case Expense(_, var date, var amount, _, _) -> …
map.forEach((_, value) -> total.add(value));
try { … } catch (NumberFormatException _) { return 0; }
```

This course targets Java 21, where `_` is not yet available without preview, so Tally names its
unused components.
