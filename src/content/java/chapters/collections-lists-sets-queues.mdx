Always declare variables and parameters with the **interface** (`List`, `Set`, `Map`) and choose the
implementation only where the object is created.

```java
List<String> names = new ArrayList<>();   // callers see List; the choice of ArrayList stays local
```

## Lists — ordered, indexed, duplicates allowed

### `ArrayList`

A resizable array. Reading by index is instant; adding at the end is amortised constant time (the
array grows by about 50% when full, copying everything once). Inserting or removing in the middle
shifts every later element.

### `LinkedList`

A doubly linked list of nodes. Adding or removing at either **end** is constant time — but reaching
index `i` means walking `i` nodes, and every element carries two extra pointers and a node object.

<Callout type="tip" title="Use ArrayList">
In practice `ArrayList` wins almost every benchmark, including many insert-heavy ones, because
contiguous arrays are cache-friendly and walking a linked list is not. When you need a queue or stack,
use `ArrayDeque`, not `LinkedList`.
</Callout>

```java
list.add("x"); list.add(0, "y"); list.get(2); list.set(2, "z");
list.remove(0);              // by index
list.remove("z");            // by value — beware List<Integer>: remove(1) removes index 1
list.indexOf("x"); list.contains("x");
list.subList(1, 3);          // a live view, not a copy
list.sort(Comparator.naturalOrder());
Collections.reverse(list); Collections.shuffle(list);
```

### Iterating and removing

<Compare>
  <Bad title="Removing inside a for-each">

```java
for (String name : names) {
    if (name.isBlank()) names.remove(name);   // ConcurrentModificationException
}
```

  </Bad>
  <Good title="removeIf, or the iterator's remove">

```java
names.removeIf(String::isBlank);

Iterator<String> it = names.iterator();
while (it.hasNext()) {
    if (it.next().isBlank()) it.remove();
}
```

  </Good>
</Compare>

`TreeSet` also gives you range queries — `first()`, `last()`, `floor(x)`, `ceiling(x)`,
`headSet(x)`, `tailSet(x)`, `descendingSet()`.

## Queues and deques

A `Queue` hands out elements in some order; a `Deque` (double-ended queue, "deck") works at both ends
and so is also a **stack**.

Each operation comes in two flavours:

<DecisionTable
  columns={['Throws on failure', 'Returns a special value']}
  rows={[
    { label: 'Insert', cells: ['add(e)', 'offer(e) → false'] },
    { label: 'Remove head', cells: ['remove()', 'poll() → null'] },
    { label: 'Look at head', cells: ['element()', 'peek() → null'] },
  ]}
/>

```java
Deque<String> stack = new ArrayDeque<>();
stack.push("a"); stack.push("b");
stack.pop();        // "b" — last in, first out

Queue<String> queue = new ArrayDeque<>();
queue.offer("a"); queue.offer("b");
queue.poll();       // "a" — first in, first out

PriorityQueue<Task> tasks = new PriorityQueue<>(Comparator.comparing(Task::deadline));
tasks.poll();       // the earliest deadline, whatever the insertion order
```

- `ArrayDeque` is the default for both stacks and queues. It does not allow `null`. The old `Stack`
  class is synchronized legacy — avoid it.
- `PriorityQueue` is a binary heap: `offer` and `poll` are O(log n), `peek` is O(1). Its iterator does
  **not** return elements in priority order.
- The thread-safe `BlockingQueue` family is covered in the concurrency part.

## Utility methods

```java
List.of(1, 2, 3); Set.of("a"); Map.of("k", "v");   // immutable (next chapter)
Arrays.asList(array);                              // fixed-size view backed by the array
Collections.unmodifiableList(list);                // read-only view of a list that can still change
Collections.emptyList(); Collections.singletonList(x);
Collections.frequency(list, x); Collections.max(list);
Collections.synchronizedList(list);                // coarse locking; prefer java.util.concurrent
Collections.nCopies(3, "x");
```

<Callout type="pitfall" title="Arrays.asList is fixed-size">
`Arrays.asList(...)` supports `set` but throws `UnsupportedOperationException` on `add` and `remove`.
Wrap it — `new ArrayList<>(Arrays.asList(...))` — if you need to grow it.
</Callout>
